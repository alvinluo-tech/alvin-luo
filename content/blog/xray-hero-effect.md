# 我是怎么给个人网站做「X 光透视人像」的

> 我做数字产品，副业是练腹肌。所以个人网站的首屏，我想让鼠标滑过 T 恤时，能看穿它——直接看到底下的训练状态。

Landon Norris 的官网首屏有两张对齐的人像照片：一张西装革履，一张赛车服。悬停时一个圆形透镜跟着鼠标走，透镜里显露出另一张照片。我第一眼看到就觉得，这个效果简直是为我量身定做的——只不过我的两个状态不是「西装 / 赛车服」，而是「穿衣服 / 练完衣服湿透」。

这篇文章完整记录这个效果从抄作业到推翻重来的全过程。最终方案没有用任何第三方库，就一个 Canvas 和两糊 PNG，大概 300 行代码。

## 先说结论：为什么我推翻了自己的几何方案

直觉上，这个效果应该这样做：在鼠标位置画一个圆，圆里显示第二张照片。

问题是「人」不是矩形。透镜是圆的，人是任意轮廓——鼠标在肩膀上时，圆里一大半是背景；移到腰腹，衣服和手臂混在一起。所以第一版我自然地想到：**用几何形状去逼近身形**。

我先后试过：

1. 一个大椭圆罩住躯干——肩膀两侧的背景露进来了；
2. 上胸一个圆 + 腹部一个圆的拼凑——肩部行了对，下腹又穿帮了；
3. 继续加圆的数量，调每个圆的半径、羽化——**越调越像在绣花**，而且只要换一张姿势稍微不同的照片，全部参数作废。

卡了两天的顿悟时刻是意识到一个问题：**「身体在哪」这个信息，本来就写在照片的 alpha 通道里。** 我的训练照是抠好背景的 PNG——每个像素的 alpha 值就是最精确的身形轮廓，精确到发丝。我之前是在用几何形状手工模拟一张现成的蒙版。

这就是所谓第一性原理：不要问「怎么用圆形逼近身体」，要问「身体的数据在哪」。

## 整体架构：三层合成

最终方案由三部分组成：

- **穿衣服层**：默认显示的底图，画在主 canvas 上；
- **训练层**：透视时显露的图，预先合成到一张离屏 canvas；
- **命中图**：训练照的 alpha 通道缩到 160×240 的灰度阵列，负责回答「光标下是不是身体」。

### 第一步：alpha 命中图

把训练照画到一个 160×240 的小 canvas 上，`getImageData` 读出像素数组。之后每次鼠标移动，只需要在数组里查一个点的 alpha 值——O(1)，快到可以每帧做。

```js
function buildHitMap(training) {
  hitCtx.drawImage(training, 0, 0, HIT_W, HIT_H);
  // 脸不变 → 抠掉脸部区域，悬停脸时不会激活
  hitCtx.globalCompositeOperation = "destination-out";
  const g = hitCtx.createRadialGradient(0, 0, 0.7, 0, 0, 1);
  g.addColorStop(0, "rgba(0,0,0,1)");
  g.addColorStop(1, "rgba(0,0,0,0)");
  // …以脸部为圆心填充这个软边椭圆
  hitData = hitCtx.getImageData(0, 0, HIT_W, HIT_H).data;
}

function bodyAlpha(nx, ny) {
  const r = Math.round((DILATE / state.w) * HIT_W); // 轮廓外扩几像素
  // 在命中图里取 (nx, ny) 周边半径 r 内的最大 alpha，返回 0~1
}
```

两个细节值得说：

- **外扩（dilate）**：光标刚滑出身体边缘 16px 内仍算命中。没有这个余量，手在轮廓上快速移动时效果会「断触」，一闪一闪的。
- **脸部抠除**：用一个软边椭圆把脸从命中图里挖掉。脸在两张照片里是一样的，悬停脸时透视毫无变化，只有一圈绿框跟着鼠标，观感很怪。挖掉之后，透镜只对躯干和四肢生效。

还有个兜底：如果页面以 `file://` 直接打开，canvas 会被跨域污染，`getImageData` 会抛异常。捕获后退化成「矩形区域判定」——精度差但至少能用。

### 第二步：透镜内的揭示 = 三次「与」运算

透镜里要显示的内容，本质上是三个条件的交集：

> 训练照的轮廓（alpha） ∩ 圆形透镜范围 ∩ 当前激活强度

Canvas 2D 的合成模式刚好是干这个的：

```js
// 离屏 canvas：先画训练照
rctx.drawImage(training, 0, 0, w, h);

// ∩ 圆形透镜：radialGradient 做软边蒙版，destination-in 只保留交集
rctx.globalCompositeOperation = "destination-in";
drawSoftLens(rctx, lens.x, lens.y, lensR);

// ∩ 激活强度：一层半透明黑罩控制淡入淡出
rctx.fillStyle = `rgba(0,0,0,${intensity})`;
rctx.fillRect(0, 0, w, h);
```

软边透镜本身也是一个小技巧：`createRadialGradient(0, 0, 0.62, 0, 0, 1)`，先 `scale(lensR, lensR)` 再画单位圆——内圈 62% 是实心，边缘 38% 线性淡出。**X 光圈**那两条描边（内圈墨线 + 外圈荧光绿）用 `source-atop` 画，它会自动只落在已有像素上，所以光圈只勾在身体轮廓上，不会画到背景里。

强度 `intensity` 和透镜位置都不要直接用鼠标值，各挂一个 lerp 缓动（0.1 / 0.16）——这是「丝滑」和「跟手」的全部秘密。

### 第三步：最关键的一步，把衣服「擦掉」

这是整个效果从「能看」到「惊艳」的一步，也是我卡了最久的地方。

上面两步做完，效果已经能看了，但仔细看会发现**割裂感**：透镜边缘处，训练照的裸身轮廓比穿衣服层细——衣服是悬垂的，衣摆比腰宽。于是在透镜边缘，会露出一圈「底层衣服的细边」，像两张纸没对齐。

第一反应是让训练照更胖一点去盖住它——又回到几何逼近的老路了。

正解还是回到物理直觉：**X 光看穿衣服时，被看穿的那部分衣服应该「消失」，而不是被人体盖住。** 所以在叠训练层之前，先在主 canvas 上把透镜范围内的衣服层擦掉：

```js
// 1) 透镜范围内擦掉穿衣服层
ctx.globalCompositeOperation = "destination-out";
ctx.globalAlpha = intensity;
drawSoftLens(ctx, lens.x, lens.y, lensR); // 同款软边蒙版
ctx.globalAlpha = 1;
ctx.globalCompositeOperation = "source-over";

// 2) 再叠上训练层 ∩ 透镜
ctx.drawImage(revealCanvas, 0, 0, w, h);
```

擦掉后露出的是纸面背景——这才是「衣服被看穿后诚实的结果」。边缘的割裂感彻底消失，透镜边缘是「衣服 → 纸面 → 身体」的自然过渡。

## 触屏：没有 hover 怎么办

手机上没有悬停，方案是「点一下上半身开启透视，透镜跟随手指滑动，点空白处关闭」。但真机上光靠这个不够——手指会挡住透镜本身。所以右下角还有一个 X-RAY 胶囊开关，一键开合。

这里埋着一个我在移动端审计时才抓到的竞态：胶囊的 `click` 和人像的 `pointerdown` 会先后触发——点胶囊时，`pointerdown` 先把透视打开，紧接着 `click` 又把它翻转关闭，净效果为零，**胶囊在触屏上永远打不开**。修法是 `pointerdown` 里先判断事件目标在不在胶囊里，是则直接 return，让胶囊独占处理。

另一个触屏专属的坑和 CSS 有关：人像卡片因为视差效果带着 `transform`，会创建独立的堆叠上下文，胶囊自己的 `z-index` 只在卡片内部生效——跨出去压不过一个 `z-index: 2` 的状态标签，被整块盖住点不到。解法很朴素：纯展示的浮层一律 `pointer-events: none`。

## 这些坑我也替你踩过了

最后列几个和 Canvas 无关、但折腾了我不少时间的坑，如果你也要做类似效果：

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| `visibilitychange` 里取消 rAF | 切回标签页动画永久停摆 | 不取消，浏览器会自动节流后台帧 |
| 重设 `canvas.width` | 位图被清空、自绘标记丢失 | resize 后把 `idleDrawn` 置回 false 允许重绘 |
| 每帧读 `getImageData` | 性能爆炸 | 只在图片加载时读一次 160×240 的小图 |
| 主题切换后透镜圈看不见 | 描边颜色写死 | 每帧读 `data-theme`，内圈墨线在暗色下换纸色 |

## 写在最后

这个效果最终的代码量不大，但它是我第一次完整地体会到「第一性原理」不是一句口号：

> 当你在用越来越多的特例修补一个方案时，多半是问错了问题。正确的数据（alpha 通道）一直都在那里，等着我停止绣花。
